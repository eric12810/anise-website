# GA4 configuration

Set distinct GA4 web data stream Measurement IDs (`G-…`) in `analytics-config.js`: `staging` for `www.staging.loveanise.co.uk` / `staging.loveanise.co.uk`, and `production` for `www.loveanise.co.uk` / `loveanise.co.uk`. The checked-in empty values disable tracking. Never reuse an ID across environments. Other hosts remain disabled. Do not publish this staging checkout to production without reviewing its POS routing and setting the production ID.

Analytics is optional. No Google script loads until a visitor accepts the banner. The persistent Analytics cookies control reopens the choice; rejecting after acceptance clears the choice and reloads so no further events are sent. The choice uses local storage and contains no customer data. The site's separate `promotion-cookie.js` is a functional returning-customer cookie, not analytics consent. Review the site's privacy/cookie notice before deployment and disclose GA4, its purpose, retention, and how to withdraw consent.

The order page sends `view_item`, `add_to_cart`, `begin_checkout`, `add_shipping_info` for delivery, and `add_payment_info`. The status page sends `purchase` only after the POS reports card order creation following Stripe confirmation or cash order acceptance. It uses a session-only, non-personal basket snapshot from checkout because the status API deliberately omits totals and lines. Purchases opened on another device or after session storage is cleared are not measured. A local-storage order-number marker suppresses refresh duplicates in the same browser. Blocking storage disables purchase tracking to avoid duplicates. The snapshot is never sent to GA with names, contact details, address, notes, promo code, or payment details. Item names and variant IDs, GBP value, and the order number are sent.

Run the website tests on the staging branch and verify in GA4 DebugView with a staging ID and synthetic orders. Check no `googletagmanager.com` request occurs before consent or after rejection; inspect event payloads for personal information. Validate card and cash purchases separately and refresh the status page to confirm one purchase. Do not deploy or use real customer orders for testing.
